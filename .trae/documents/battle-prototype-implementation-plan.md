# 可运行战斗原型实施计划

## Context

当前战斗设计稿的战报由 `assets/design.js` 中的 28 条预置事件驱动，不能按已确认的 0.5 规则实际结算。目标是在保留静态页面和直接浏览器运行能力的基础上，实现六名样例武将参与、最多八回合的自动战斗；战斗结果可通过记录确定性地逐步回放。数值是待验证的原型参数，不据此声称已完成平衡。

## 推荐实现

将战斗模拟与页面展示分离，并通过普通延迟脚本依赖顺序加载，兼容直接打开 HTML：数据、规则、引擎、回放控制器，最后是原有设计页脚本。新增脚本使用 IIFE，统一挂在 `SanguoBattle` 命名空间；引擎及规则层不访问 DOM、计时器或页面状态。

战斗输出包括初始状态、带序号的结构化事件、最终结果，以及规则版本、参数和随机种子。所有命中、目标抽取、控制、暴击和浮动随机均走可注入的种子随机源。事件记录实际判定及兵力变化；回放只读取记录，不再运行规则或重抽随机数。

## 实施步骤

1. **抽离样例数据与原型参数**：新增 `assets/battle-data.js`，集中定义现有六名武将、六个战法、编队和公式参数；沿用页面样例属性与兵力。未定的战后恢复比例及跨战伤兵不纳入模拟。
2. **实现规则函数**：新增 `assets/battle-rules.js`，实现实时排序、目标合法性、伤害/治疗公式、控制判定、状态实例与计时、持续效果快照及效果队列排序。规则显式区分完整回合和目标行动次数计时，不以单个剩余回合数推断全部状态寿命。
3. **实现战斗引擎**：新增 `assets/battle-engine.js`，调度战斗开始、回合开始、尚未行动者选择、行动前时点、主动、普攻、行动后时点及回合末队列。每个攻击原子完成绑定子效果后检查胜负；战斗结束取消后续独立效果。覆盖准备战法释放时重新选目标、持有者倒下/战斗结束时取消准备、控制检查、追击和八回合平局。
4. **接入确定性回放**：新增 `assets/battle-replay.js`，增加随机种子输入、运行模拟和结果摘要；保留播放、暂停、下一事件、重置。播放只更新当前事件与兵力快照；重跑先停止旧计时器并生成新记录。编队快照显示初始兵力，结果显示胜负、结束回合、主将剩余兵力与决定性事件。
5. **更新页面与脚本装配**：修改 `sanguo-battle-design.html` 的 `#demo` 和脚本引用；删除静态两回合/28事件及预置随机措辞。保留现有设计曲线和导航，曲线参数从原型数据读取。修改 `assets/design.js`，仅保留 Mermaid、tabs、曲线初始化，不再承载战斗模拟或静态战报数据。
6. **增加规则测试**：新增无依赖 Node 测试 `tests/battle-tests.js`，用固定种子和可控随机序列断言关键规则、胜负边界、事件一致性及兵力约束；不引入构建工具或第三方包。

## 验证

- 在 Windows PowerShell 中运行 `node .\tests\battle-tests.js`，覆盖实时速度变化、每回合双机会、控制与准备、原子绑定效果、目标与治疗边界、持续快照和计时、回合末排序、主将胜负/平局、八回合上限及同种子结果一致。
- 用浏览器打开现有静态页面，确认直接加载无模块/路径问题；实际运行战斗，逐步回放、播放、暂停、重置并重新模拟；检查事件兵力与结果快照一致、无重复计时器及控制台错误。
- 最终执行差异格式检查，并确认静态战斗日志和旧的“两回合、28事件”文案已移除。
